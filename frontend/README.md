# frontend (Web UI)

React + TypeScript SPA (Vite). Talks only to the Control Plane API (`VITE_API_BASE_URL`, default `http://localhost:8000/api/v1`) — never directly to PBS or PVE — and contains no exclusive business logic (manifest §4.2). Design follows [`../docs/design/RESURGAM-Styleguide.md`](../docs/design/RESURGAM-Styleguide.md), which supersedes the manifest's §26 for frontend specifics (ADR 0008).

## What's here

- **Auth**: `contexts/AuthContext.tsx` — break-glass login (`fetch` + JSON) and real OIDC (full-page redirect to `/auth/oidc/login`, session handed back via a URL fragment at `/auth/callback` — ADR 0008). Session token in `localStorage`, sent as `Authorization: Bearer` on every API call (`api/client.ts`); a 401 anywhere logs the session out automatically.
- **i18n**: `i18n/` — English and German (`locales/en.json`, `locales/de.json`), browser-language auto-detected on first visit, explicit choice persisted (`resurgam.language` in `localStorage`). Switch from the avatar menu.
- **Theme**: `contexts/ThemeContext.tsx` — light/dark/system via `data-theme` on `<html>`, matching the styleguide's token structure (`styles/tokens.css`). Persisted (`resurgam.theme`).
- **Avatar menu**: `components/AvatarMenu.tsx` — account info, language switch, theme switch, sign out. The styleguide's global-header "user" slot.
- **Navigation**: `nav/navTree.ts` — the full tree from the styleguide §8.1. Entries without a real page render a shared "not part of this milestone yet" placeholder (`pages/NotAvailablePage.tsx`) rather than being hidden or faked.
- **Real pages this slice**: Login (2026-09-14 — now two forms: local-account sign-in as the primary form, break-glass tucked behind an "Emergency access" toggle so it stays available without competing visually with the account most people will actually use; a local login that returns `mfa_required` renders an inline MFA step — method picker when more than one is available, TOTP/recovery-code as a plain code field, WebAuthn as a "use security key" button driving the real browser `navigator.credentials` API via `lib/webauthn.ts`, no client library), Profile (`/profile`, not in the manifest's nav tree at all — reached only via the avatar menu, ADR 0010: change password; TOTP enrollment with a real QR code rendered client-side via the `qrcode` package from the server's `otpauth://` URI; WebAuthn security-key registration/removal; recovery-code generation, shown once with a save-it-now warning; the whole page shows a single explanatory message instead for break-glass/SSO accounts, which have no local password to manage), Administration → Users & Roles (`/administration/users-roles`, implements a manifest-named nav placeholder for the first time — create a local account, disable/enable, and manage its role assignments in a click-to-open modal reusing the same `Modal` component as PBS/PVE config); Overview (now also shows an Alarms panel — manifest §9.2's Dashboard alarm states, computed server-side, sorted critical-first, an "all clear" badge when empty rather than the panel just vanishing); Infrastructure → PBS Instances, PVE Targets (both — 2026-09-14 — gained a click-to-open `Modal` "window" per row showing the full config read-only, with an Edit button that switches the same modal into a form; `api_token` is never returned by any endpoint, so its edit field is always blank with a "leave blank to keep the current value" placeholder — filling it in rotates the stored secret, backed by a new `PATCH /pbs-instances/{id}` / `PATCH /pve-clusters/{id}`, TLS-fingerprint re-verified the same way `POST` already does whenever host/port/fingerprint actually change; PVE's modal also edits its linked-PBS-instances set, a full-replacement multi-select, not a merge), Datastores (not from the manifest, a UX rewrite requested after first review — 2026-09-14) is now one expand/collapse directory tree — PBS Instance → Datastore → Namespace → Backup Group → Snapshot — instead of three separate table pages (the old Backup Groups/Snapshots pages and their routes are gone; everything lives inline here now). Namespaces are grouped and counted explicitly (the real dev PBS's `site-b/tenant-b`, `site-b/Firestorm`, `tenant-a` are genuinely different sub-trees, invisible as a *grouping* in the old flat table even though the data was already there — see the namespace-scoping bug fix earlier in `docs/milestone-1-pbs-pve-api-assumptions.md`). Each level lazy-fetches only when expanded (`useQueries`, keyed by the set of currently-expanded ids) rather than eagerly loading every datastore's groups or every group's snapshots up front — real data is 135 groups/1321 snapshots on one datastore alone. Inline controls are unchanged from the old pages, just relocated: a datastore's customer/role picker sits on its row, a group's customer-override/protection-policy picker sits on its row (showing "Inherited (‹datastore's customer›)" — ADR 0009 — same as before). Each group row also shows PBS's own reported `owner` (e.g. `tenant-a@pbs`) when present, 2026-09-14 — purely informational, not wired to the customer picker in any way. Jobs → Backup Jobs / Verification / Prune & Garbage Collection / Replication & Sync (one `TasksPage` component, client-side filtered by `task_type` — not four fake pages; Replication & Sync also shows configured Sync Jobs, manifest §8, above the task table — shown separately, not correlated to a specific job's "last run", since that correlation is unverified against a real PBS); Administration → Customers (2026-09-14, was list+create only — gained the same click-to-open `Modal` detail/edit pattern as PBS/PVE, plus real content instead of "raw": its assigned datastores and a live billing summary, read straight from `/billing/customers/{id}`; also gained Import/Export CSV buttons, requested directly — two new `client.ts` helpers, `downloadFile`/`uploadFile`, since a file download and a multipart upload don't fit `apiRequest`'s always-JSON contract; import shows a created/updated/per-row-error summary inline, no separate confirmation step), Protection Policies, Pricing Plans (global default + per-customer override; per-unit rate split three ways — VM/LXC/Host, 2026-09-14, not one flat per-unit rate, since the three are typically priced differently — CRUD only); Reporting → Capacity & Trends (per-datastore usage %, logical size and dedup ratio, group/snapshot counts, 24h/30d change, last GC — manifest §9.3), Tenant Usage (the billing computation ADR 0009's Pricing Plans were built for — per customer: billed VM/LXC/Host counts, estimated physical bytes with an "estimate incomplete" badge when a contributing datastore has no usage measurement yet, resolved pricing plan source, and the estimated monthly cost). Protection Policies, Pricing Plans, Capacity & Trends, and Tenant Usage each add real content to a nav entry the styleguide's own §8.1 tree only named as a placeholder (Tenant Usage was already in the tree; the other three add one entry beyond it).
- **Shared components**: `components/` — `QueryState` (centralizes loading/error/forbidden/empty handling so every page gets it for free), `DataTable`, `StatusBadge` (icon+text+color, never color alone), `ConfirmActionDialog` (native `<dialog>`), `EmptyState`, `InlineAlert`.

## Local development

```bash
npm install
npm run dev      # http://localhost:5173, expects the backend on :8000 (see ../backend/README.md)
npm run build    # tsc -b && vite build
npm run test     # vitest
```

Requires the backend running with `FRONTEND_ORIGIN`/`FRONTEND_SUCCESS_URL` matching this dev server's origin (defaults on both sides already match: `http://localhost:5173`).
