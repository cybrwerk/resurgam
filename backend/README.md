# backend (Control Plane)

FastAPI Control Plane. Milestone 1 is complete; Milestone 2's manifest §17 checklist (Tasks/Logs, Usage-Historie, Protection Policies, Sync-/DR-Status, Alarmzustände) is functionally complete — this backend now also serves the frontend in `../frontend/` (CORS, and the OIDC callback hands off to it — ADR 0008).

## What's here

- `src/resurgam_api/models/` — SQLAlchemy models: `User` (now also `password_hash`, nullable — set only for a real local account, ADR 0010; null for break-glass and OIDC-only users), `Role`, `UserRoleAssignment` (tagged `source`: `manual`/`oidc` — ADR 0007), `TotpCredential`/`WebauthnCredential`/`RecoveryCode` (not from the manifest, ADR 0010 — MFA for local accounts; a TOTP secret is stored the same way as a PBS/PVE API token, via `SecretReference`, not a new mechanism; `TotpCredential.confirmed_at` stays null until proven working once, so an enrolled-but-unconfirmed secret never becomes a login requirement), `Customer` (with Swiss/German-convention `debitor_number` + 3-letter `match_code`, both unique — not from the manifest, added on request), `SecretReference` (reference only, no secret material — manifest §14), `AuditEvent` (append-only, enforced by a database trigger), `PbsInstance`, `PveCluster`/`PveClusterPbsInstance`, `LocalSecretValue` (interim secrets storage, ADR 0005), `Datastore`/`DatastoreCustomerAssignment` (1:1 enforced via a unique constraint on `datastore_id`; `role` — `primary`/`offsite`, not from the manifest, ADR 0009 — a secondary/DR copy doesn't double-count toward per-VM billing), `BackupGroup`/`BackupSnapshot`/`TaskRun` (Collector output, manifest §9.4 — `BackupGroup.resolved_name` is populated from PBS's per-group notes field, not PVE, see connectivity bullet below; `BackupSnapshot.size_bytes` is `BigInteger`, widened from `Integer` after live verification showed real byte counts overflow INT4; `BackupGroup.customer_id` is a nullable per-group override of the datastore's own customer, ADR 0009; `BackupGroup.owner`, not from the manifest — PBS's own reported owner e.g. `tenant-a@pbs`, taken from the most recently synced snapshot, surfaced read-only in the frontend as a hint, never used for auto-assignment), `ProtectionPolicy` (manifest §9.5 — belongs to one customer, a backup group opts in via its nullable `protection_policy_id`), `UsageMeasurement` (manifest §9.3/§8 — append-only, one row per Collector sync per datastore; distinguishes PBS's physical, deduplicated `used_bytes` from `logical_bytes`, the undeduplicated sum of current snapshot sizes — the manifest's own named distinction between "PBS-Datastore-Belegung" and "logisch geschützte Datenmenge"), `PricingPlan` (not from the manifest, ADR 0009 — global default when `customer_id` is null, else a per-customer override; at most one of each enforced by partial unique indexes; per-unit rate split three ways, `price_per_vm_month`/`_ct_month`/`_host_month`, not one flat rate), `SyncJob` (manifest §8 — config data, upserted like `PbsInstance`, not append-only; field shapes unverified against a real PBS, see connectivity bullet below).
- `alembic/` — migrations, one file per schema change in [`alembic/versions/`](alembic/versions/) (numbered `NNNN_<what>.py`, read the newest file for the head revision). `0001` seeds the six roles from manifest §7. The API container runs `alembic upgrade head` on every start.
- `src/resurgam_api/inventory/protection.py` — `evaluate_protection_status()`: the manifest §9.4 OK/Warning/Critical/Unknown status for one backup group, computed on read from its policy (or UNKNOWN if none is assigned) and current state — never stored, since it's a function of live data, not a fact. `sync_dr_required` on a policy is stored but intentionally not evaluated yet — that needs Sync-/DR-Status (EPIC 6, not built), a stated gap like the Collector's own.
- `src/resurgam_api/inventory/usage.py` — `compute_usage_changes()`: manifest §9.3's daily/monthly change in used bytes, computed from RESURGAM's own stored `usage_measurements` history (not PBS's own separate history array — see the connectivity bullet). Returns `None` rather than `0` once the history doesn't yet reach back that far.
- `src/resurgam_api/inventory/alarms.py` — `compute_alarms()`: manifest §9.2's Dashboard alarm states ("überfällige Backups"/"Datastore-Auslastung"), computed fresh on every call, never stored. Two signals: a group's `protection_status` being critical/warning (skipped if no policy assigned), and a datastore's latest usage measurement crossing 80%/95%. Instance-unreachable and task-failure signals are deliberately excluded — both already have their own visible status elsewhere (PBS Instances page's health badge; task history's status column), so a duplicate alarm would add no new signal.
- `src/resurgam_api/inventory/billing.py` — `compute_customer_billing()`: not from the manifest — the actual computation `PricingPlan` (ADR 0009) was built for but nothing read until now. Per customer: counts `primary`-role backup groups (own override, else the datastore's assignment) for the per-unit fee, split by `BackupType` (VM/CT/Host each priced separately, 2026-09-14); sums every matching group's own logical bytes (its snapshots' summed `size_bytes`) scaled by *its own datastore's* dedup ratio for the per-GB fee (primary and offsite both count here — it's real disk either way); resolves the customer's pricing plan (customer override, else the global default) and applies it. A datastore with no usage measurement yet contributes 0 bytes and flips `physical_bytes_estimate_complete` to `false` rather than blocking the whole computation. Computed fresh on every call, never stored — same pattern as protection/usage/alarms. Verified against real data on the dev PBS (135 groups — 91 VM/43 CT/1 Host — ~2.16TB estimated physical bytes).
- `src/resurgam_api/auth/` — `AuthenticatedUser`/`RoleAssignment` types; `breakglass.py` (bcrypt credential check) and `oidc.py` (Authlib Authorization Code + PKCE against authentik, `provision_user_from_claims` mapping `resurgam-<role-key>` groups to global roles — ADR 0007) both feed the same `create_session_token`/`get_current_user`/`require_role` interface (ADR 0004), so every business endpoint's RBAC enforcement is identical regardless of login method. `scope.py` — `visible_customer_ids()`, the shared customer-scope filter reused by `datastores.py`/`customers.py`/`pricing_plans.py`; `effective_group_customer_id()` (ADR 0009) resolves a backup group's own customer override, or its datastore's assignment, or none. `local.py` (bcrypt password hash/verify for real local accounts — ADR 0010, `User.password_hash`, distinct from break-glass's single env-configured credential); `mfa.py` (TOTP secret generation/verification via `pyotp`, recovery-code generation/hashing); `sessions.py` also issues two purpose-scoped, short-lived JWTs beyond the real session token — an MFA challenge token (`create_mfa_challenge_token`, between a correct password and a satisfied second factor) and a WebAuthn ceremony token (`create_webauthn_ceremony_token`, carries a registration/authentication ceremony's server challenge back to the client and back, since there's no server-side session store to stash it in) — `verify_session_token` explicitly rejects any token carrying a `purpose` claim, so neither can reach a business endpoint on its own.
- `src/resurgam_api/secrets/` — `SecretsProvider` protocol and `LocalEncryptedSecretsProvider` (Fernet-based interim implementation — ADR 0005). Not OpenBao; see the ADR for the swap plan.
- `src/resurgam_api/net/tls_pinning.py` — real TLS certificate fingerprint pinning (raw-socket preflight handshake + SHA-256 compare), tested against an actual locally-generated self-signed certificate, not mocked.
- `src/resurgam_api/connectivity/` — `probe_pbs`/`probe_pve` (version/reachability), `list_datastores`, `list_namespaces`, `list_snapshots`, `list_tasks`, `get_group_notes`, `list_datastore_usage`, `list_remotes`, `list_sync_jobs` (PBS only) — outbound calls against a configured PBS instance or PVE cluster. **PBS mostly verified against a real PBS 4.2 instance** (2026-09-13/14) — this caught and fixed three real bugs: (1) `list_tasks` used the wrong field names, `type`/`id` instead of PBS's actual `worker_type`/`worker_id`, which would `KeyError` on every real call; (2) a task-type mapping gap (scheduled jobs report a `"...job"`-suffixed `worker_type`, e.g. `prunejob`, distinct from their ad-hoc counterpart); (3) `list_snapshots` only ever queried the root namespace — PBS's snapshot-listing endpoint is scoped to exactly one namespace per call and doesn't recurse, so a real datastore with an empty root but 135 backup groups under other namespaces looked completely empty until this was fixed (`list_namespaces()` + one call per namespace, aggregated). **Exception**: `list_remotes`/`list_sync_jobs` (`config/remote`/`config/sync`) were reachable but empty on the tested instance, so their field shapes are best-effort from documentation only, not verified — flagged in both docstrings. **PVE now verified too** (2026-09-14, against a real PVE 9.2 cluster) — `probe_pve()` and the `/pve-clusters` create + test-connection flow worked correctly on the first real attempt, no bugs found; only the version probe exists so far, nothing beyond it. See [`../docs/milestone-1-pbs-pve-api-assumptions.md`](../docs/milestone-1-pbs-pve-api-assumptions.md) for the full verified/unverified breakdown, `tests/test_connectivity_pbs_api.py`/`tests/test_connectivity_pve_api.py` for regression tests locking in the real (verified) response shapes, and `tests/test_connectivity_sync_jobs.py` for the still-unverified PBS ones (its docstring says so explicitly).
- `src/resurgam_api/collector/sync.py` — the Collector: normalizes PBS backup groups/snapshots and task history into the models above, idempotently; captures one `usage_measurements` row per datastore per sync (manifest §9.3) using PBS's live capacity numbers plus group/snapshot counts computed from the just-synced data; and upserts configured Sync Jobs (manifest §8) per instance, best-effort linking `local_store` to an imported `Datastore` by name. Runs in-process, on-demand only (ADR 0006) — not yet the standalone, scheduled worker the manifest describes.
- `src/resurgam_api/filerestore/browse.py` — manifest §13's File Indexing/Recovery: browses and downloads individual files out of a snapshot, dispatching on `BackupGroup.backup_type` to `resurgam_worker.pbs_client.catalog` (CT/host, wraps `proxmox-backup-client catalog dump`/`restore`) or `.file_restore` (VM, wraps `proxmox-file-restore`) — **both confirmed live**, CT/host against a real PBS 4.2 instance (2026-09-14/15), VM against a real PVE 9.2 node (2026-09-15, a real Windows Server VM backup, standalone CLI, no PVE API needed). Calls `restore-worker` in-process via an editable path dependency, same simplification as the Collector (ADR 0011 — also documents real bugs live testing caught on both paths: three `proxmox-backup-client` CLI quirks for CT/host, and for the VM path an `AF_VSOCK`/AppArmor block plus a zombie-reaping issue that turned out to be masking the real root cause — mismatched package versions/repos, not a fundamental flaw).
- `src/resurgam_api/api/v1/` — `/health`, `/readiness`, `/version`, `/auth/breakglass-login`, `/auth/oidc/login`, `/auth/oidc/callback` (now a browser redirect handing the session to the frontend via a URL fragment, not a JSON body — ADR 0008), `/auth/whoami`; `/auth/local-login` (real local accounts — ADR 0010, returns a full session when no MFA is enabled, else an MFA challenge token + the caller's available methods); `/auth/mfa/verify-totp`, `/auth/mfa/verify-recovery-code`, `/auth/mfa/webauthn/authenticate-options` + `/authenticate` (all consume the MFA challenge token from `/auth/local-login`, issue a real session on success); `/auth/change-password` (rejected with `no_local_password` for break-glass/OIDC accounts, which have no password to change); `/users` (`platform_admin`-only: create/list/get/disable/enable, `/assign-role`/`/unassign-role`/`/role-assignments` — a fresh account has no role assignments until one is granted); `/mfa/status`, `/mfa/totp/enroll`+`/confirm`+`DELETE`, `/mfa/webauthn/register-options`+`/register`+`DELETE /mfa/webauthn/{id}`, `/mfa/recovery-codes/generate` (self-service, any authenticated local account — enrollment/management, distinct from the login-time `/auth/mfa/*` endpoints above); `/customers` (create/disable/enable/`PATCH` `platform_admin`-only — `PATCH` is a partial update, `slug` isn't editable, list/get customer-scope filtered); `/customers/export`/`/customers/import` (not from the manifest, requested directly, `platform_admin`-only — CSV, `name,slug,debitor_number,match_code[,disabled]`; import upserts by `slug`, one bad row is reported and skipped rather than failing the whole file, `disabled` is exported for round-trip fidelity but ignored on import); `/pbs-instances`, `/pve-clusters` (probe-tls, create, list, get, test-connection, disable, enable, delete, `/pbs-instances/{id}/available-datastores` + `/pbs-instances/{id}/datastores` for import, `/pbs-instances/{id}/sync` to run the Collector, `/pbs-instances/{id}/tasks` — all `platform_admin`-only); `/datastores` (assign-customer — now also takes a `role`, unassign-customer, delete are `platform_admin`-only, but list/get are open to any authenticated user and **server-side filtered by customer scope**); `/datastores/{id}/backup-groups` (per-group effective-customer filtering, not just "is the datastore in scope" — ADR 0009) and `/backup-groups/{id}/snapshots` (same); `/backup-groups/{id}/assign-customer`/`unassign-customer` (`platform_admin`-only, the per-group override itself); `/datastores/{id}/usage` (same scope filtering — latest measurement, capped history, and computed daily/monthly change); `/protection-policies` (create/delete `platform_admin`-only, list/get customer-scope filtered, reusing the same `visible_customer_ids()`); `/backup-groups/{id}/assign-policy` and `/unassign-policy` (`platform_admin`-only, rejects assigning a policy from a different *effective* customer than the group's with `409 protection_policy_customer_mismatch`) — both return the group with its freshly computed `protection_status`; `/pricing-plans` (create/delete `platform_admin`-only — the global plan, `customer_id: null`, is platform_admin-only to read too; list/get customer-scope filtered otherwise); `/pbs-instances/{id}/sync-jobs` (`platform_admin`-only — configured Sync Jobs, manifest §8, refreshed by the same `/sync` call as tasks/inventory); `/alarms` (any authenticated user, customer-scope filtered — manifest §9.2's Dashboard alarm states); `/billing/customers` and `/billing/customers/{id}` (any authenticated user, customer-scope filtered — the billing computation ADR 0009's `PricingPlan` was built for); `/backup-groups/{id}/snapshots/{id}/files` and `/files/download` (manifest §13 — `restore_operator` or `platform_admin`, scoped to the group's effective customer, 404-not-403 on denial), `/file-restore/capability` (any authenticated user — manifest §18.12-style report so the frontend can show "not available here" instead of failing opaquely).
- `src/resurgam_api/errors.py` / `middleware.py` — unified `{code, message, correlation_id, details}` error format and an `X-Request-ID` correlation ID on every response (manifest §4.2). `main.py` also adds `CORSMiddleware` (for the frontend's dev origin) and `SessionMiddleware` (OIDC PKCE state).

## Local development

Requires Docker (for Postgres) and [`uv`](https://docs.astral.sh/uv/).

```bash
docker compose --env-file /dev/null -f docker-compose.dev.yml up -d
cp .env.example .env   # fill in SESSION_SECRET; BREAKGLASS_* for break-glass login; OIDC_* for authentik login
uv sync
uv run alembic upgrade head
uv run uvicorn resurgam_api.main:app --reload
```

`resurgam-worker` is an editable path dependency on `../restore-worker` (ADR 0011) — both directories must be checked out side by side (as they are in this monorepo) for `uv sync` to resolve it. Editing `restore-worker/` source while `--reload` is running needs a manual restart: `--reload` only watches `backend/`.

## Tests

Tests need the same Postgres container running (they are not started automatically, to avoid surprising container lifecycle side effects), but use their own `resurgam_test` database on it — created automatically on first run — rather than the interactive `resurgam` database from `.env`. This is deliberate: pointing tests at the same database an interactively-run server writes to lets real dev-session rows (e.g. manual `curl` smoke-testing) leak into assertions that count rows, which happened once during development and produced flaky failures. Each test also runs in a rolled-back transaction on top of that, so tests never leave data behind between runs either.

```bash
docker compose --env-file /dev/null -f docker-compose.dev.yml up -d
uv sync
uv run pytest -q
```

Set `TEST_DATABASE_URL` to point tests at a different database entirely if needed.

`--env-file /dev/null` stops Compose from auto-loading this directory's app `.env` for `${...}` interpolation — harmless since this compose file doesn't use any, but `.env`'s bcrypt password hash contains `$` sequences that otherwise trigger noisy "variable is not set" warnings.
